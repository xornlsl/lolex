# 회원 기능 반영 상태

## 적용됨

- `member_sheet`: 관리자가 직접 입력하는 명단. 추가·수정·삭제, 전체 인원 표시. 승인된 STAFF/SUPERADMIN만 접근.
- 가입 시 명단의 성명·생년월일·롤 닉네임#태그가 모두 일치해야 함. 양 끝 공백을 제거한 뒤 대조하며, 명단을 기존 회원으로 자동 채우지 않음.
- 승인된 회원과 이름이 같으면 `이미 가입된 정보가 있습니다.`로 차단. 동명이인 승인 경합도 DB에서 차단.
- 같은 명단의 중복 가입 신청 차단. 명단 삭제는 이미 가입한 계정을 삭제하지 않음.
- 내전 점수는 빈칸/0 또는 1~50 정수. 신규 가입 시 종합 및 5개 포지션 모두 `1000 + 점수 * 10`. 기존 회원 레이팅은 재계산하지 않음.
- `profile_aliases`: 본인이 부계정을 즉시 등록. 다른 회원의 본계정/부계정 및 자신의 본계정과 중복되는 Riot ID는 등록 불가. 내 정보 및 회원 검색에서 작은 괄호로 표시, 부계정 닉네임 검색 지원.
- `match_player_stats` 및 `get_most_champions`: 같은 회원 ID로 본·부계정 합산. 확정된 경기의 챔피언 사용 횟수 상위 3개, 평균 K/D/A, 합계 기반 KDA, 승률, 승패수. 내 정보/회원 검색 화면 연결.

## 아직 연결하지 않은 부분

- 외부 분석 API는 사용하지 않기로 함. 실제 롤 클라이언트 전적 상세 화면 샘플을 받아 OCR 영역, 챔피언 아이콘 판별, 승리팀과 사이트 팀 매핑을 검증해야 함.
- 현재 캡처 업로드·자동 결과 확정·결과 확정 후 기록 화면 이동은 미구현. 기존 승리팀 선택 방식이 동작함.
- 실제 캡처가 `match_player_stats`를 채우는 경로는 아직 없음. 기록이 없으면 모스트 챔피언은 빈 상태를 표시함.
- 현재 기존 프로필에 동일한 Riot ID를 가진 회원들이 있으므로, 캡처의 닉네임이 여러 참가자와 일치할 경우 자동으로 한 명을 선택하면 안 됨.
- 캡처 업로드 UI 구현 시 App.jsx의 전역 `업로드` 클릭 가로채기를 리그 화면으로 한정하거나 제거해야 함.
- 결과 저장과 레이팅 반영은 서버에서 하나의 트랜잭션으로 처리하고, 이미 확정된 경기의 재업로드로 통계/레이팅이 중복 반영되지 않게 해야 함.

## 확인

- `node --test tests/member-sheet.test.mjs`: 입력 검증 및 관리자 접근 조건.
- `supabase/tests/signup_aliases_stats.sql`: 명단 일치, 중복 가입/승인, 부계정 충돌, 초기 레이팅, 삭제 후 계정 유지, 본/부계정 챔피언 합산. 트랜잭션 롤백 사용.
- `node --env-file=.env.local scripts/smoke-signup.mjs`: 실제 배포 API의 잘못된 점수·명단 불일치·비로그인 접근 차단. 가입을 성공시키지 않는 테스트.
- Vite 빌드 완료. 기존 App.jsx의 Hook 관련 lint 경고는 남아 있음.
